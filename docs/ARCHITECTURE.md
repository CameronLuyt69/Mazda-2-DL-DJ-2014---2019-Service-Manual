### Inside a wiring SVG

These are Illustrator exports with named layers:

- `IRO` (Japanese for "colour") holds the coloured wires as `line`, `polyline` and `path` elements.
- `SEN` holds outlines, and `TEXT` holds the labels.
- `HIGHLIGHT > g#P003100` holds the circuit for fault code **P0031:00**. The wiring section of the contents uses the same ID in `…_P003100_GO.html`.
- `LINK > circuit > g#CR-<key>[:CR-<key>…]` are links to other diagrams. They can point at several diagrams.
- `LINK > connector > g#CR-<connector>` are connector hotspots. These include grounds (`G03`) and joint connectors (`C-49`), which have no name entry.

## The new viewer

```
index.html            app shell (top bar, sidebar, view, dialogs)
serve.mjs             zero-dependency static server (Node)
app/
  main.js             router, contents tree, pages, search UI, lightbox, shortcuts
  data.js             loads toc/ewd data, route <-> data-href mapping
  ewd.js              wiring diagram viewer (lazy-loaded)
  search.js           main-thread client for the search worker
  search-worker.js    MiniSearch in a Web Worker
  search-config.mjs   index options, query normalisation, synonyms (shared with the build)
  util.js             helpers: escaping, storage, gestures, term highlighting
  styles.css          app styles and design tokens (light/dark)
  content.css         injected into original pages at view time
  vendor/minisearch.mjs  MiniSearch 7.1.2 (MIT), vendored
  data/               generated by scripts/build-data.mjs
scripts/
  build-data.mjs      builds app/data from the original files
  smoke-test.mjs      serves the app and checks that every link target exists
```

### Routes

All routes are hash routes, so links can be bookmarked and back/forward work.

| Route | Shows |
|---|---|
| `#/` | Home |
| `#/p/<path>?q=&a=` | A manual page in an iframe. `q` highlights search terms; `a` scrolls to an anchor |
| `#/e/<circuit>?hl=<P-code>&cn=<connector>&q=` | Wiring diagram |
| `#/f/<path>` | A PDF |
| `#/search?q=&k=<kinds>&s=<sections>` | Full search results |

The build writes contents links as short "data hrefs":

- `p:<path>` is a page.
- `e:<circuit>[:<hl>[:<connector>]]` is a wiring diagram.
- `f:<path>` is a PDF.

`data.js` converts these to and from routes. Links clicked inside original pages go through `legacyUrlToHash`, so `*_GO.html` stubs open the new diagram viewer instead of a popup.

### Original pages

Topic pages load in a same-origin iframe. Because the `id*.html` pages are already real HTML, there was no reason to rewrite them. On load, the viewer:

- injects `content.css`, which modernises the type, warnings, tables and figures and adds dark mode
- intercepts link clicks so navigation stays in the app
- makes figures open in the lightbox
- builds the "On this page" outline
- highlights search terms

### Search

- **Index:** MiniSearch, chosen over FlexSearch and Pagefind:
  - it is small, has no dependencies and ships as ES modules
  - it supports fuzzy and prefix search, field boosts and nested AND/OR queries, which the synonym handling needs
  - its index serialises to JSON, so it can be **prebuilt**
- **Load time:** indexing in the browser took about 3 s. Loading the prebuilt 5.5 MB index takes about 0.2 s, and a query takes about 5 ms.
- **Data split:** the build writes three files:
  - `search-index.json`
  - `search-meta.json` (title, breadcrumb, section, kind and route per document)
  - `search-text.json` (page text, 13 MB)

  The worker loads the index and meta first, so search is ready quickly. The text loads in the background and is only used for snippets.
- **Documents:**
  - one per topic page
  - one per wiring diagram, carrying all its labels and connector names
  - one per fault-code wiring highlight
  - one per connector

### Diagram viewer

- **Loading:** the SVG is fetched and inlined.
- **Zoom:** done by changing the `viewBox`, so it stays sharp at any level. The view is stored as a top-left point plus a scale.
- **Wire tracing:** the viewer builds geometry from the `IRO` layer. Two segments are joined when one segment's end lies on the other segment (shared ends and T-junctions). Plain crossings are not joined.
- **Fault-code highlights:** the `HIGHLIGHT` groups are hidden until you select one, then copied into an overlay with an animated dash.

## Not changed

These original files are left in place and still used by the legacy viewer:

- **Scraper leftovers:** 358 `Descr.WD3`, 608 `@C=*_O=*.html` directory listings, 371 `default.htm` and 2 `*.BAK` files.
- **Fake SVG copies:** the `*.svg` "copies" in `esicont/srvc/html/` and `js/` are web pages, not SVGs.
- **Junk in `esicont/menu/`:** files named after scraped URLs, for example:
  - `gtm.js`
  - `google.tagmanager.debugui2.queue`
  - `www.google-analytics.com`
  - `kickstarter.com`
  - `youtube.com`, `youtube-nocookie.com`
  - `player.vimeo.com`
  - `a.post`, `ul.nav`

The new viewer never loads any of these. They can be deleted in a separate clean-up once the legacy viewer is no longer needed.

## Known limits

- The new viewer needs the local server; it does not work from `file://`.
- PDFs open in the browser's built-in PDF viewer. A bundled PDF.js viewer would mostly duplicate the HTML pages, which already have search and highlighting.
- Wire tracing follows drawn geometry, so it does not continue through components such as relays or modules, which is correct electrically. It also does not continue onto another diagram: use the link boxes at the diagram edge for that.
- The current-flow animations are the original CreateJS canvases, shown in a dialog.
